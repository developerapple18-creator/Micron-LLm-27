# Micron Law V3 — عقود الاستيضاح والتقرير ومراجعة القبول 0.1

## 1. نهج عقد واحد لثلاث نتائج
اعتماد مخطط استجابة Structured Outputs واحد باسم `micron_case_analysis_v1`، مع الحقل `kind` الذي يختار `clarification` أو `report` أو `blocked`. الحقول الأخرى موجودة ومطلوبة في JSON Schema، لكن الفرع غير المستخدم يكون `null`؛ ويتأكد الخادم من ذلك بعد الاستلام. لا يُطلب من Replit تقرير كفاية المعلومات قانونيًا؛ النموذج وحده يختار النتيجة بناءً على معلومات القضية.

## 2. عقد الاستيضاح (clarification)
- `clarification.context`: ملاحظة قصيرة للمحامي تُبيّن سبب الحاجة للمعلومات، دون إفشاء تعليمات داخلية.
- `clarification.questions`: عادة 1–3 أسئلة. لكل سؤال `id` مؤقت خاص بهذه الاستجابة، و`question` بلغة محايدة، و`options` من اختيارات النموذج الملائمة، و`allow_unknown` و`allow_not_applicable` عند الحاجة.
- **الواجهة**: تعرض الأسئلة داخل تدفق المحادثة ومربع الكتابة نفسه، مع أزرار خيارات وإجابة نصية حرة دائمًا؛ «غير ذلك» قدرة ثابتة في الواجهة وليست حصرًا ضمن الاختيارات. لا يُرغم المحامي على اختيار إجابة يعلم أنها خاطئة. يسمح بإجابة «لا أعلم» دون الدوران في السؤال نفسه.
- تُحفظ إجابة المحامي عند إرسالها فقط، وتتصل بمعرّف السؤال، وتُقدَّم إلى الاستدعاء التالي. لا تتطلب كل نقرة استدعاء API مستقلًا.
- لا تُعد أسئلة النموذج أو إجابات المستخدم أدلة مثبتة قضائيًا بمجرد حفظها.

## 3. عقد التقرير (report)
- `report.title` عنوان مختصر للقضية لا يفضح بياناتها في شاشة أخرى.
- `report.sections` تحتوي **ثمانية أقسام فريدة بالترتيب** `summary,facts,characterization,evidence,position,legal_basis,risks,conclusions`.
- `blocks` في كل قسم وحدات نصية قصيرة تحتوي `text`, `basis` (تصنيف المصدر/الاستنتاج) و`source_refs` (معرّفات مصادر حقيقية صادرة عن التطبيق/سجل الاسترجاع).
- أنواع `basis` لا تُعد تقييمًا قضائيًا للحجية: `lawyer_statement`, `documented`, `legal_source`, `analysis`, `conditional`, `unverified`.
- `alerts` للتنبيهات المستقلة ذات الأثر العالي، مثل خطر فوات موعد أو تعذر قراءة ملف حاسم. لا تكررها بلا حاجة في كل قسم. تسمي `attachment_id` من قائمة المرفقات المصرح بها فقط أو `null`.
- `change_summary` تملأ عند تحديث تقرير سابق فقط وإلا `null`.
- تُثبت هوية النسخة والوقت والمالك في الخادم، لا في النص الذي يولّده النموذج.
- إن كانت قاعدة قانونية غير موثقة، لا يُسمح بوضعها في خانة `legal_source` بمرجع مختلق؛ تُعرض مشروطة أو غير متحققة.

## 4. عقد التعذر (blocked)
يُستخدم عند استحالة تقديم تحليل مفيد ولو جزئيًا، وليس لأي تعارض مستندات أو غياب مادة نظامية منفردة. يحتوي `message` و`needed` بنقاط عملية. أخطاء API، والمهلة، والانقطاع، أو فشل حفظ التقرير حالات فنية من الخادم، وليست نتائج قانونية يولدها النموذج.

## 5. حدود JSON Schema الرسمية
- يُرسل داخل `text.format` في Responses API بصيغة `json_schema` و`strict:true`.
- جذر المخطط object وليس union؛ جميع الحقول مطلوبة و`additionalProperties:false` لكل object. يُسمح بـ`null` في الفرع غير المستخدم.
- لا يكفي توافق JSON لإثبات صحة القانون أو المصدر. حالات الرفض أو الاستجابة غير المكتملة تُعالج قبل الحفظ والعرض.

## 6. تحقق الخادم بعد الإخراج — حد أدنى، بلا محرك قانوني جديد
1. التحقق من شكل JSON، ثم مطابقة `kind` مع الفرع الوحيد غير-null.
2. عند `clarification`: عدد الأسئلة 1–3، لا أسئلة أو خيارات فارغة، معرّفات الأسئلة غير مكررة.
3. عند `report`: ثمانية أقسام فريدة بالترتيب؛ لا أقسام ناقصة، ونص قابل للعرض. لا يعني ظهور الأقسام أن الملف المقروء شامل.
4. مطابقة جميع `source_refs` مع سجل مصادر **هذه القضية وهذه المحادثة** فقط؛ عدم السماح للموديل بابتداع معرّف أو ربط ملف قضية أخرى. لا يُسمح بإبراز صفحة لم يسجلها المصدر فعليًا.
5. مطابقة `attachment_id` في التنبيه مع قائمة المرفقات المعروضة للمحامي.
6. التحقق من أن `documented` و`legal_source` لا تُقدمان بوصفهما توثيقًا إذا لم يوجد رابط مصدر فعلي صالح؛ وتبقى المطابقة القانونية للمضمون مهمة النموذج وتقييمات الاختبار والمراجعة البشرية.
7. مراجعة حدود النص وميزانيته وحالة الاستدعاء قبل اعتماد النتيجة؛ عند خلل العقد لا تُظهر نجاحًا كاذبًا ولا تدخل إعادة محاولات بلا سقف.

## 7. نطاق البيانات والأمن
- **Case context** يعطى من الخادم بعد إثبات هوية المحامي وملكيته للقضية.
- سجل المصادر source registry مُعرّفات غير قابلة للتخمين تربط ما أُتيح للنموذج حقيقةً بموقع المصدر. الأداة قد تعيد اسم ملف فقط بلا صفحة؛ لا تخترع الصفحة.
- فصل مرجع الأنظمة العامة عن ملفات القضايا السرية؛ منع الاسترجاع العابر للقضايا بأي مسار، بما فيه vector stores والأدوات.
- مفتاح OpenAI والأوامر الداخلية في الخادم، ولا تُرسل بيانات الاعتماد للنموذج.
- وضع تحديث التقرير يتلقى النسخة السابقة ذات الصلة مع الأدلة الجديدة؛ لا يُعاد ضخ كل الملف الطويل تلقائيًا.

## 8. واقع مشروع Replit الحالي (مرجعية المرحلة الأولى)
المستودع يحتوي REST للقضايا والرسائل والمرفقات، بما فيه `POST /api/cases/:caseId/messages`، وصلاحيات المالك، ورفع التخزين الخاص. لا يحتوي مسار AI مطبقًا بعد. حد الرفع الأولي 50 MiB **للتخزين**؛ لا يعني توافق الملف مع حد OpenAI للإدخال المباشر (50 MB مجموع ملفات الطلب). المرفقات الأصلية لا تُقرأ أو تُفهرس في Replit حاليًا. لا نطلب تعديل هذا الأساس الآن.

## 9. مدخل التشغيل المُقترح (مواصفة، لا بيانات متوفرة بالفعل)
`task=case_analysis`, `phase=initial|answer|update`, `represented_party=null|string`, `lawyer_message`, `case_context`, `attachment_registry` (status of stored originals and AI-access), `source_registry` (only sources genuinely accessible in this run), `previous_report` (when update), `tool_capabilities`, `runtime_limits`.

## 10. مواصفات الاختبار والقبول
اختبار بوقائع كافية بلا مرفقات، وملف دعوى طرفه غير معلوم، وتحويل مالي بلا سبب معلوم، وحكم بمواعيد تبليغ غير ثابتة، ومرفقات متعارضة، ومجموعة من 3 ملفات بينها PDF طويل ممسوح، ومصدر قانوني لم يثبت نفاذه، وإضافة دليل جديد، ورفض المحامي الاستيضاح أو إجابته «لا أعلم»، واختبارات حقن برومبت عبر PDF، وعزل محاميين، وفشل الاتصال/الاستجابة/الحفظ، واستدعاءات مكررة. **شروط القبول**: صحة المسار والفرع، سلامة الإحالات وصدق حدود القراءة، تقبل الطرف والتاريخ، جودة قانونية في عينة تحكيم بشرية، عدم تسرب ملفات قضية أخرى، وقياسات التوكنات والزمن والتكلفة لكل حالة. هذه مواصفات اختبار وليست اختبارات منفذة.

## 11. قرارات نطاقية تمنع تضخم التطوير
- لا تنشئ محركات OCR أو PDF Parser أو قواعد متجهات أو GraphRAG داخل Replit لمجرد وجود التصميم.
- لا تنشئ وكيلًا قانونيًا ثانيًا يراجع كل إجابة؛ اجعل فحوص الجودة الملائمة في طلب النموذج وأجر اختبارات مستقلة خارج التشغيل الحقيقي.
- لا تضف مهام الصياغة والاستئناف والنقض والعقود خلال تفعيل تحليل القضية.
- لا تربط ناجز ولا تنسب لها حدود أحرف عامة في منتج التحليل؛ ستنظم في عقود التسليم الخاصة لاحقًا.
- لا تختار نموذجًا أو ميزانية إنتاجية نهائية قبل اختبار عيّنات فعلية؛ لا تفترض أن `previous_response_id` يلغي تكلفة سياق المحادثة.
