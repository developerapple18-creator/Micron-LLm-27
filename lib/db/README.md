# قاعدة البيانات — PostgreSQL وSQL

مالك المشروع والمهندس المسؤول: خالد.

تعريف قاعدة البيانات في ملفات SQL داخل `migrations`. يبقى `src/index.js` محوّل اتصال PostgreSQL للتطبيق، ويصدّر `pool` كما كان، ولا ينفّذ ترحيلات عند بدء الخادم.

| الملف                                    | الوظيفة                                                  |
| ---------------------------------------- | -------------------------------------------------------- |
| `migrations/0001_initial_schema.sql`     | 18 جدولًا و24 فهرسًا و25 علاقة مرجعية                    |
| `migrations/0002_immutable_records.sql`  | حماية المستندات المنشورة وسجلات التدقيق والقبول          |
| `migrations/0003_report_protections.sql` | قيود مساحة التقارير وحماية النسخ المحفوظة                |
| `sql/report-workspace.sql`               | SQL التاريخي الإضافي المستخدم في اختبارات مساحة التقارير |
| `scripts/migrate.mjs`                    | تنفيذ صريح للترحيلات وتسجيل بصماتها                      |

## التشغيل

بعد تثبيت الاعتماديات وضبط `DATABASE_URL` لقاعدة PostgreSQL 16 أو أحدث:

```sh
pnpm --filter @workspace/db run migrate:status
pnpm --filter @workspace/db run migrate
pnpm --filter @workspace/db test
```

اختبارات المنفّذ السبعة تعمل دون اتصال بقاعدة بيانات. لاختبار قيود SQL نفسها على قاعدة اختبار معزولة بعد تطبيق الترحيلات، شغّل `tests/constraints.sql` بواسطة psql مع `ON_ERROR_STOP=1`. ينشئ الاختبار بيانات مؤقتة داخل معاملة ثم يتراجع عنها؛ لا تشغّله على قاعدة الإنتاج.

يستخدم التنفيذ معاملة واحدة وقفلًا لمنع تنافس منفّذي الترحيلات، ويسجّل اسم كل ملف وبصمة SHA-256 في `public.schema_migrations`. التشغيل التالي يتجاوز الملفات المنفّذة، ويرفض تغيير ملفات سبق تطبيقها. أضف ملف SQL مرقّمًا جديدًا لأي تغيير مستقبلي.

الترحيل الأول لقاعدة فارغة. قواعد البيانات الموجودة لا تحتاج إلى تغيير صيغة بياناتها: فهي PostgreSQL أصلًا. يرفض المنفّذ تطبيق التهيئة الأولى فوق جداول موجودة؛ يجب مقارنة مخططها واعتماد خط أساس منفصل قبل إدارتها بهذه الترحيلات. لا يوجد أمر حذف أو إعادة تهيئة إجبارية.

`migrate:status` يعرض السجل والملفات المعلّقة دون إنشاء جداول أو تطبيق DDL. ملفات SQL تعمل ضمن معاملة المنفّذ؛ تشغيلها مباشرة عبر psql يحتاج إلى `ON_ERROR_STOP` ومعاملة صريحة. الملف التاريخي `immutable-records.sql` يحتفظ بنسخة SQL من ترحيل الحماية للتوافق؛ استخدم المنفّذ لتسجيل التطبيق.
